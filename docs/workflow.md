# 从资料到商品发布的工作流程

## 1. 盘点与去重

对 PPT、PPTX、PPSX、PPTM 文件记录文件名、大小、内容哈希、页数、来源目录和分类。按文件内容去重，保留原文件不覆盖。历史本地记录中，两份来源库共 2,533 个演示文件，整理后正式演示文件为 1,478 个：职业规划 784、创新创业 694。数量口径不包含配套说明文件，也不是“全库空白模板套数”。

## 2. 按用途重新分类

职业规划按专业案例与参考、优选比赛展示模板、人物访谈、图片化获奖成品参考、方法教程、旧版基础模板与单页素材组织。其中专业与职业方向入口为 109 个；图片化参考单独标注不可编辑。创新创业按精选 PPT 与 8 个行业方向、通用模板、比赛指南与填写参考组织。

## 3. 抽样与真实页面核对

先读取页面结构和文字，再查看封面与正文，不只凭文件名选样。两款最终各选 4 套，分别覆盖 86 页与 82 页。后台历史脚本中的抽样编号与分类规则依赖当时的源库，不应该直接套用到别人的文件列表。

## 4. 制作连续九图

第一张集中展示 4 款封面；第 2–9 张按每套两张的顺序完整展开选样。首图 1:1，详情图 3:4。生成稿需要检查图文关系、是否虚构奖项和销售承诺、细字误差、人物信息、二维码及裁切，再导出 JPG。原 PPT 不随展示图生成而改写。

## 5. 准备平台文案

标题在第一行，与正文作为一个输入框的完整文案。公开样例采用无 emoji 文本。价格、类目、履约时效与售后约定需按实际能力填写。平台限制可能变化，应以上传入口当时的校验为准；本仓库只固定现有成品尺寸，不承诺通用平台规则。

## 6. 云端交付核验

历史流程包括断点上传、元数据比对、目录核对、匿名分享访问和抽样 SHA-256 回读。元数据一致与每份文件全文回读是不同证据：历史记录没有证明 1,478 份演示文件均已逐字节回读。

这些历史脚本保存在 [workflows/](../workflows/README.md)。它们依赖私有清单、自己的云盘凭据以及外部适配器，公开版本默认禁用执行；没有把云盘交付链接或提取码放入仓库。

## 7. 平台提交与订单履约

本地素材保存 → 平台提交 → 商品 ID 与商品列表核验 → 已付款订单触发 → 发送与发货状态核验。每个阶段都需要独立记录。当前两款案例只到“发布素材已完成”；2026-10-10 的后台验证只覆盖本地功能与鉴权，不构成实际上架或全自动履约成功。
