# 本地运行与运维

本项目把商品资料准备、九图与文案案例、闲鱼后台本地服务分开处理。运行后台需要显式检出上游固定版本，并应用本仓库补丁；本仓库不携带第三方上游的完整源码。

## 环境准备与启动

1. 按 [快速开始](getting-started.md) 准备 Python 3.11 及 Playwright 浏览器依赖。具体依赖版本以当前仓库配置和固定上游版本为准。
2. 检查 `scripts/bootstrap_upstream.sh`，确认其检出提交为 `e8fe7ba4239614fe64d194cf3bed8a3aa16d5ab6`，并应用 `patches/manual-verification-status-fix.patch`。
3. 根据本地环境创建自己的配置和凭据。不要把口令、密钥、Cookie 或账号资料写入仓库；不要使用示例默认凭据对外开放服务。
4. 通过 `runtime/setup_local.py` 初始化本地服务，再按项目提供的启动入口运行。`runtime/start_gudong.py` 用于启动上游应用，`runtime/manage_service.py` 用于管理本地服务，`runtime/browser_runtime.py` 配置浏览器运行参数。
5. 先在本机检查服务启动、管理页面可访问性、数据库初始化和人工验证流程，再由操作者自行决定是否进行平台操作。

浏览器适配应保持环境可移植，不依赖 Codex 专属目录、缓存位置或本机浏览器路径。运行时根据已安装的 Playwright 浏览器进行解析；若找不到兼容浏览器，应清楚报告环境依赖缺失，不尝试读取其他用户或工具的会话数据。

## 本地数据保护

数据库、浏览器用户目录、会话文件、Cookie、日志和备份都可能包含账号或交易信息，应只保存在受控的本机运行目录中。不要将这些文件提交到 Git、复制到公开示例、上传到工单或放入案例截图。发布前检查 Git 跟踪清单和待提交差异，不能只依靠 `.gitignore`。

服务只应按本地使用需要开放端口。对外访问管理页面前，需要操作者自行配置适当的网络隔离、访问控制与 HTTPS。第三方平台可能调整接口、登录校验或自动化策略；遇到验证或异常时应暂停自动操作并由用户处理，不应把验证绕过作为正常运行要求。
